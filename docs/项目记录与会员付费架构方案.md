# 项目记录与会员付费架构方案

> 本文档记录 `aap-baby-guide` 站点从零搭建的全过程，以及未来「账号系统 + 按账号笔记 + 付费解锁章节」的架构方案。
> 当前状态：方案阶段，**尚未实现**。

---

## 一、对话与决策记录

### 1. 起点：PDF 能否被精确阅读
- 原始素材：`version7.pdf`（《美国儿科学会育儿百科（第 7 版）》，31MB，1133 页）。
- 结论：该 PDF **带真实文字层**（非扫描图片），`pdftotext` 可**无损、精确**抽取正文；封面等个别页是图片，插图内文字抽不出。
- 因此所有内容以 **PDF 文字层**为准（`version7.md` 存在少量抽取噪点，弃用）。

### 2. 目标：把长篇书籍做成按章节的重点摘要网页
- 形态：GitHub 项目，托管到 `JackieLam` 账号（github.com）。
- 要求：可扩展（后续逐章补充）、首个版本先做「第一部分 · 第 1 章」。
- 确定信息（经确认）：
  - 仓库名 **`aap-baby-guide`**，**Public**，GitHub Pages **立即开启**。
  - 在线地址：<https://jackielam.github.io/aap-baby-guide/>

### 3. 关键架构决策：内容与展示分离（为未来 AI 问答预留）
- 用户提出未来想加 **AI 问答**，希望抽取时顺带产出「方便 agent 阅读的无损原文」，并让网页架构适合 agent 检索原文再做总结。
- 决策：**静态站足够**。每章产出两份文件：
  - `raw.txt` —— PDF 无损抽取原文（带页码标记），供 agent 检索 / 未来 AI 引用；
  - `summary.json` —— 结构化人读摘要，渲染器据此生成页面。
- 未来 AI 问答只需在此基础上加一个调用大模型的 serverless 后端，**现有静态架构不改**。

### 4. 已交付的功能（已上线）
- 零构建静态站：`index.html` + 渲染器 `assets/js/app.js` + `assets/css/styles.css`（含深色模式、移动端适配、即时搜索）。
- 内容注册表 `content/manifest.json`：登记卷首（front）与各章（chapters）。
- 内容块 schema：`para / keypoints / warning / position / tip / checklist / table` + 术语表 `glossary`。
- 已整理内容：**引言《最好的礼物》**、**第 1 章《为新生儿的到来做准备》**，各附 `summary.json` + `raw.txt`。
- 抽取脚本 `scripts/extract_chapter.sh`（给定页码范围无损抽取某章原文）。

### 5. 内容忠实度要求（重要约束）
- 用户明确要求：**内容必须完全基于原文，不得产生任何书外内容。**
- 当前做法：`pdftotext` 无损抽取 → 仅依据 `raw.txt` 压缩归纳，不掺外部知识；摘要为「压缩转写」而非逐字照抄，每条可回溯到 `raw.txt`（已抽样核验通过）。
- 可选增强：为每个要点标注 PDF 页码（进一步强化可核对性）——待定。

### 6. 画重点 / 笔记功能（已上线）
- 顶栏新增「阅读 / 📝 Note」标签。
- 选中正文即弹出工具条：四色高亮 + 添加笔记；点击已有高亮可编辑/删除。
- `#/notes` 页面按章节分组展示全部笔记，可跳转原文/删除/复制全部。
- **存储方式：浏览器 `localStorage`（键 `aap-notes:v1`）。**

### 7. 发现的问题：笔记不跨设备
- 现象：换一个终端/浏览器登录，看不到之前的笔记。
- 原因：`localStorage` 作用域为「同一浏览器 + 同一域名」，**不跨设备、不跨浏览器、无账号概念**。
- 纯静态站（GitHub Pages）没有后端数据库，数据只能存在访问者自己的浏览器里。

### 8. 新需求：账号系统 + 按账号笔记 + 付费解锁（本方案主题）
- 账号系统：注册/登录。
- 每个账号有自己的笔记。
- 付费墙：免费会员只能看「引言 + 第 1 章」；付费后解锁后续全部章节。
- 结论：**当前纯静态站不足以支撑**，需引入后端。详见第二部分。

### 9. 提交规范
- Git 提交按功能/function 拆分；提交信息**不得包含任何 AI/agent/模型署名**（遵循全局约定）。
- 已有提交：站点骨架+第1章 / 引言内容 / 卷首渲染支持 / Note 标签与样式 / 画重点与笔记引擎。

## 二、会员付费架构方案（草案，待实现）

### 2.1 需求
1. **账号系统**：注册、登录、会话保持。
2. **按账号笔记**：笔记与用户绑定，跨设备可见（登录即同步）。
3. **付费墙**：
   - 免费会员：仅可访问「引言」「第 1 章」。
   - 付费会员：解锁后续全部章节；需记录会员状态（是否付费、到期时间）。

### 2.2 为什么静态站不够
| 需求 | 静态站 | 根因 |
|---|---|---|
| 账号/登录 | ❌ | 需服务端校验与会话签发、持久化用户 |
| 按账号笔记 | ❌ | 需数据库按 `user_id` 存取 |
| 付费解锁 | ❌ | **前端隐藏 ≠ 保护**：公开静态文件可被直接 URL 访问/开发者工具抓取 |

### 2.3 核心安全原则：付费内容必须服务端鉴权
- 付费章节内容**必须移出公开静态目录**，放入只有后端可读的私有存储/数据库。
- 访问流程：前端携带登录凭证 → 后端校验「已登录 **且**（该章免费 **或** 用户为有效付费会员）」→ 通过才返回内容。
- 免费章节（引言、第 1 章）可继续作为公开静态文件。

### 2.4 目标架构

```
  浏览器 (前端：现有渲染器基本保留)
    │   登录态 (JWT / 会话 cookie)
    ▼
  Serverless API（鉴权内容网关）
    ├─ Auth 服务          登录/注册/会话
    ├─ 数据库             users(含会员状态) / notes
    ├─ 私有内容存储        付费章节 summary.json + raw.txt
    └─ 支付 webhook        收款成功 → 更新会员状态
```

- **保留**：`app.js` 渲染器、`summary.json` 数据结构、内容/展示分离设计。
- **改动**：
  - 内容来源：免费章走静态；付费章改为 `GET /api/chapter/:id`（带 token）。
  - 笔记：从 `localStorage` 改为 `/api/notes` 读写数据库（渲染逻辑不变）。
  - 新增登录/注册/「升级会员」UI。
- **托管迁移**：GitHub Pages 仅静态，需迁到可同时托管静态前端 + serverless 函数的平台（**Vercel / Netlify / Cloudflare Pages**，均有免费额度；代码仓库仍在 GitHub）。

### 2.5 推荐技术栈

| 层 | 推荐 | 说明 |
|---|---|---|
| 托管 + API | **Vercel** 或 **Cloudflare Pages** | 静态前端 + serverless 函数一体，免费额度足够起步 |
| Auth + 数据库 | **Supabase**（Postgres + Auth + 行级权限 RLS） | 「每人只能读写自己的笔记」用 RLS 配置即可，后端代码极少 |
| 支付 | **Stripe**（海外）/ **微信支付·支付宝**（中国大陆） | **取决于目标用户所在地区（关键待定项）** |

> 备选：Auth 用 Clerk/Auth0/Firebase Auth；数据库用 Firebase。但 Supabase 的 RLS 对本场景最省心。

### 2.6 数据模型（示意）

```sql
-- 用户（Supabase Auth 自带 auth.users，这里存业务字段）
profiles (
  id            uuid primary key,        -- = auth.users.id
  email         text,
  is_paid       boolean default false,
  plan          text,                    -- 如 'free' / 'pro'
  paid_until    timestamptz,             -- 会员到期时间（订阅制）
  created_at    timestamptz default now()
)

-- 笔记（按用户隔离，RLS：user_id = auth.uid()）
notes (
  id            uuid primary key,
  user_id       uuid references profiles(id),
  chapter_id    text,                    -- 'intro' / 'ch01' ...
  quote_text    text,                    -- 画重点选中的原文
  note_text     text,                    -- 笔记内容
  color         text,
  occ           int,                     -- 第几次出现（用于重新定位高亮）
  created_at    timestamptz default now()
)
```

- 章节的「免费/付费」归属无需单独表，可在 `manifest.json` 增加 `access: "free" | "paid"` 字段，由内容网关读取判断。

### 2.7 API 接口（示意）

| 方法 & 路径 | 作用 | 鉴权 |
|---|---|---|
| `POST /api/auth/*` | 注册/登录/登出（多由 Supabase SDK 直接处理） | — |
| `GET /api/chapter/:id` | 返回某章 `summary.json`；付费章校验会员 | 需登录 |
| `GET /api/chapter/:id/raw` | 返回原文（同上鉴权；为未来 AI 预留） | 需登录 |
| `GET /api/notes` | 取当前用户全部笔记 | 需登录 |
| `POST /api/notes` | 新增/更新笔记 | 需登录 |
| `DELETE /api/notes/:id` | 删除笔记 | 需登录 |
| `POST /api/checkout` | 创建支付会话（Stripe/支付宝） | 需登录 |
| `POST /api/webhook/pay` | 支付回调 → 置 `is_paid=true` / 更新 `paid_until` | 平台签名校验 |

### 2.8 付费→解锁流程
1. 用户点「升级会员」→ 前端调 `POST /api/checkout` → 返回支付页链接。
2. 用户在支付平台完成付款。
3. 支付平台回调 `POST /api/webhook/pay`（带签名）→ 后端校验后更新该用户 `is_paid` / `paid_until`。
4. 之后用户请求付费章 → 内容网关校验通过 → 返回内容。

> 注意：务必以 **webhook** 为准更新会员状态，不要仅凭前端「支付成功」跳转就解锁（前端可伪造）。

### 2.9 分阶段落地建议
1. **阶段 0**：托管迁移到 Vercel/Cloudflare（前端零改动，先跑通部署）。
2. **阶段 1**：接 Supabase——注册/登录 + 笔记入库（暂不收费，验证账号与笔记同步）。
3. **阶段 2**：付费章节移入私有存储 + 内容网关 API（实现「免费只给引言+ch1」的鉴权）。
4. **阶段 3**：接支付 + webhook（打通「付费→解锁」）。
5. **阶段 4（可选）**：在已鉴权的 `raw.txt` 之上接入 AI 问答。

### 2.10 待定决策（Open Questions）
- **支付地区**：目标用户主要在中国大陆还是海外？→ 决定微信/支付宝 vs Stripe。
- **计费模式**：一次性买断 vs 订阅制（月/年）？→ 影响 `paid_until` 逻辑与 webhook 处理。
- **迁移范围**：是否保留 GitHub Pages 作为「免费版入口」，付费功能走新平台？还是整体迁移。
- **版权合规**：付费分发第三方版权书籍的中文摘要存在版权风险，商业化前需评估授权问题。
